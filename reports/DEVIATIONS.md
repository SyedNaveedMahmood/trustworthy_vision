# Deviations and unresolved protocol issues

Recorded before any confirmatory scoring, 2026-10-16 (Asia/Dhaka).

1. Native Windows is used for the initial VLM smoke. WSL has no installed distribution configured for execution. No driver changes were made. CUDA and BF16 must be measured before claiming compatibility.
2. The initially empty workspace lacked Git and Python. Portable Git and uv-managed Python 3.11 were installed outside the repository, with an isolated repository virtual environment.
3. No humans are available to perform the two-rater semantic edit audit. Automated shape/geometry checks cannot satisfy semantic validity: HUMAN_AUDIT_PENDING.
4. **Unresolved control construction:** docs/05 requires label-free off-target sampling for each candidate; docs/03 describes the oracle negative candidate as the off-target control in a 13-image factorial. These are not equivalent. A negative candidate chosen by relevance labels must not become an inference-time control. Swapping the positive and negative as mutual controls gives z_minus = -z_plus, equal MAD penalties, and makes lambda irrelevant to pair rankings. A shared independent label-free control needs additional edits unless a justified design reuses it. Do not lock confirmatory evaluation until this is explicitly resolved and costed on development data.
5. No new benchmark, substitute annotations, fake LaMa output or invented literature baseline will be used to fill missing inputs. Synthetic shapes are infrastructure diagnostics only.
6. E0 rendering repair, before development: initial default Pillow bitmap letters were visually too small at 512px inference resolution. Replaced them with bundled Pillow scalable font at 4% of the source long edge (minimum 20px), white letters on black badges above each box, and 3px box outlines, uniformly on every condition. Initial Qwen/Smol records are retained as `*_overlay_v0_smoke.json`. This is an infrastructure repair evaluated on the same debug inputs, not an independent efficacy comparison or a development accuracy gate.
7. Installation failures: streamed CUDA-wheel download was replaced by resumable official-host range downloads with full publisher SHA-256 verification. An intermediate automatically resolved CPU torch was replaced by the intended 2.7.1+cu128 before any model forward. No mixed-precision or mixed-build experimental rows resulted. SmolVLM required num2words; its initial processor import failure is retained. Pytest collection initially included ignored third-party source tests; project testpaths are now explicitly `tests/`.
8. E1 followed the flagged E0 grounding debug screen solely to quantify competence on the specified 40 unseen development images/task. Full E0 PASS was withheld; no E2–E5 method evaluation proceeded through the failed prerequisite. This flagged diagnostic advancement is explicit, not an erased gate failure.
9. Development preparation used automatic single-reference-object eligibility and same-global-answer-group distractors for GQA, without completing the intended relation/spatial balancing or human ambiguity review. RefCOCOg candidate selection favored same-category/area-matched objects but overlap/texture audit is unfinished. No rows were removed after predictions; competence results apply to these automatically constructed diagnostic subsets. Broader task validity is unverified.
10. LaMa was executed on CPU in Python 3.8 with official torch 1.8.0, preserving the VLM CUDA environment. Protobuf was constrained to 3.20.3 and the conflicting OpenCV distributions replaced by one headless 4.5.5.64 build. The official prediction source was unmodified. Two successful outputs had identical SHA-256; this is infrastructure replay, not semantic operator validation.
11. Statistical diagnostics use two-sided Wilson accuracy intervals and 2,000 paired image bootstrap replicates for image-versus-text differences. Descriptive ECE uses ten equal-width bins. None of these is a substitute for the unexecuted H2 primary method comparison or a confirmatory lock.
12. The original `configs/pilot_v1.yaml` is invalid YAML: `operators` mixes a sequence with sibling mapping fields. This was found when adding strict CLI config parsing after E1. The list was nested under `operators.panel`, preserving every value. Earlier E0/E1 entrypoints used the documented model IDs, 12/40 sample counts, seeds, four labels, BF16, batch 1, sequential loading and budget values directly; no claim is made that the invalid original YAML was parsed or drove those runs. Runtime pins record the executed settings. Regression tests now parse the repaired protocol and verify its limits and panel.
